# Echo 表情库管理（系统默认 + 个人）

Echo 聊天表情分为系统默认库和个人库。机器人另有一套独立图库：所有机器人继承系统机器人表情，机器人创建者可以补充该机器人的专属表情。用户手动发送的表情不会进入机器人图库。

## 谁可以看到和管理

| 资源 | 谁能从选择器选择 | 谁能上传/下架 | 下架后已发送消息 |
|---|---|---|---|
| 系统默认 Emoji/表情包 | 所有小队成员 | 小队管理员 | 图片继续显示 |
| 个人 Emoji/表情包 | 仅上传者 | 上传者 | 图片继续显示，频道成员可查看 |
| 系统机器人表情 | 所有机器人都可供模型挑选 | 小队管理员 | 图片继续显示 |
| 单机器人专属表情 | 该机器人可供模型挑选 | 机器人创建者或小队管理员 | 图片继续显示 |

“系统默认”和“个人”是资源可见范围；“卖萌”“游戏”“开心”等是每个库内部的分组，两者不冲突。个人表情不会出现在朋友的表情选择器中，也不能通过手工构造消息 ID 发送。

## 在聊天中上传用户表情包

1. 打开频道消息框旁的表情选择器。
2. 选择“表情包”。日常 Emoji 使用内置的标准 Unicode Emoji，不需要上传或维护自定义 Emoji。
3. 在库范围中选择“系统默认”或“我的表情”。普通成员只能向个人库上传；管理员可以选择系统默认库。
4. 选择多张图片后，在同一个上传面板里逐张填写表情包名称和分组，再统一上传。
5. 需要时使用分组旁的加号创建分组。只能重命名/删除自己创建的个人分组；系统分组由管理员维护。

系统库上传后对全体成员可见。个人库上传后只有本人可选。个人表情发到频道后会成为普通频道消息，所有有权限查看该频道的人都能看到图片。

支持 PNG、JPEG、GIF、WebP。单张表情包上限 2 MiB；每个个人库最多 200 项，系统表情库最多 200 项。上传者或管理员可从对应库移除资源；历史消息仍保留图片。

## 给机器人补充表情

### 所有人都能给自己创建的机器人加专属表情

1. 打开“用户设置 → AI 机器人”，小队成员可以创建机器人。
2. 创建后选择该机器人，打开“机器人表情图库”。
3. 选择“上传到当前机器人”，点“上传表情”。
4. 依次输入名称、情绪分组（如“卖萌”）和适用说明，再选图片。
5. 确保“机器人能力 → 机器人发表情包”已启用。机器人会结合人设、对话和图库说明选择是否发送。

机器人创建者和小队管理员可以修改机器人的人设、频道安装和工具权限；只有小队管理员能配置全小队共用的 DeepSeek API Key。机器人专属图库也可由创建者或管理员维护。

### 管理系统机器人表情

小队管理员在任一机器人的“机器人表情图库”中选择“上传到系统默认”，按相同步骤上传。新上传的系统表情会进入每个机器人可用的候选库，不需要逐个复制。管理员可以在图库列表中下架系统表情。

模型只会在一次正常回复过程中调用 `sticker.send`，图片作为单独消息发送；机器人不会仅因图库里有图片而主动发消息，也不保证每次对话都发表情。建议说明中写清楚适用情绪和不适用场景，避免含义相近的图片过多。

## 本地和 VPS 部署

新增图片通过已鉴权的 API 上传到 `echo-uploads` 持久化卷，数据库保存名称、分组、归属和存储信息。日常上传、改名和下架不需要编辑 JSON、不需要执行同步脚本，也不需要重建容器。

升级到支持这套功能的版本时，在项目目录执行：

```bash
docker compose up -d --build api web
```

API 启动时会自动执行表情范围迁移：旧小队内置资源归入系统默认库，旧成员上传资源按原上传者归入个人库；旧机器人图库继续只属于原机器人。部署前仍应备份 Postgres 和 `echo-uploads` volume。Windows Docker Desktop 本地测试与 VPS 都使用同样的管理页面。

`expression-packs/` 和 `ai-sticker-packs/` 文件导入方式暂时保留作开发、批量初始化和旧资源迁移；普通用户添加新表情应使用管理页面。运行期图片来自 uploads 持久化卷，Compose 的只读目录挂载只是源文件/兼容导入，不是在线上传目录。

## 资源故障排查

- 上传失败：确认图片格式和单张大小符合限制，API 容器健康且 `echo-uploads` 可写。
- 个人表情在朋友的选择器里看不到：这是个人库隔离的预期行为；如果希望所有人能选用，由管理员上传到系统默认库。
- 机器人不发表情：确认 `sticker.send` 已开启、机器人已安装到当前文字频道、API Key 已配置，并在对话中明确提出希望用表情回应。
- 图片曾发送后资源被下架：历史消息应继续显示。备份/迁移时同时保留数据库和 uploads volume。
