# Windows 游戏启动（首版）

运行 `npm run build:desktop`，输出 `dist/windows/<构建时间>/Echo.exe`（构建日志会给出路径）。
依赖 Windows Rust MSVC 工具链、Windows SDK 和 WebView2 运行时。构建产物复用系统 WebView2，不附带完整浏览器。

先启动本地 Docker 服务，再打开 EXE，进入左下角「用户设置 → 游戏与启动」：

1. 点击「浏览文件」选择经典版 `war3.exe`，或点击「搜索指定目录」选择游戏所在的父目录。搜索支持进度、取消和候选结果确认。
2. 程序检查同目录的 `Game.dll`，路径保存到本机应用配置目录 `game.json`，不上传到服务端。
3. 配置自动保存，所有房间共用；回到开黑房间点击「启动魔兽」。以安装目录为工作目录直接启动，无 shell 命令、额外参数或管理员提权。
4. 客户端每 1.5 秒查看本次启动的进程是否退出；同一客户端会话内阻止重复启动。退出客户端不会结束游戏。

搜索跳过重解析点（符号链接、目录联接）和无法访问目录，最多扫描 200,000 个目录、保留 100 个结果；达到上限时提示缩小搜索范围。只保存用户确认的一个路径，兼容旧版本 game.json 配置。

## 当前边界

- 这是本地开发桌面版，API 与 WebSocket 默认指向 `http://localhost:8080`。可用 ECHO_SERVER_URL 编译到同一个服务器地址，脚本同时设置 API、中转端点与 CSP。
- HTTPS 服务器构建的 Windows 客户端优先通过 UDP 40000 连接 QUIC 游戏中转；诊断面板可选自动回退或强制 WSS/TCP 对照。桌面机所在网络需允许出站 UDP；服务端配置见 `warcraft-relay.md`。
- Windows 客户端会将联机诊断和 Rust panic 写入 `%APPDATA%\app.echo.squad\logs\echo-diagnostics.log`。复现闪退后请保留该文件；日志会记录联机阶段、错误和 panic 位置，不记录房间票据。
- 安装文件检查不代表版本或文件真实性校验。请使用可信安装，并在游戏内确认 1.24e。现已读取 Game.dll（优先）或 war3.exe 的 Windows 文件版本资源，并显示原始数字版本；无法读取时显示未知。不会把数字版本未经确认地映射成补丁名称。
- 只跟踪本次启动的 war3.exe；客户端重启后不会识别之前启动的游戏，也不跟踪程序派生的其他进程。
- 游戏启动成功不等于已加入局域网对局。现已实现房主加最多七名加入者的发现/转发实验，见 warcraft-relay.md；多人真实对局兼容性未验证。地图一致性检查、邀请深链打开桌面端尚未实现。
- 默认开发身份仍未替换为真实账号鉴权；请勿直接开放当前服务到公网。
- 未进行真实魔兽安装启动或多人联机测试。

桌面页面从包内加载，远程页面不授予本机启动权限。原生接口只提供状态、文件选择和已选择游戏的启动，不提供任意命令执行接口。
